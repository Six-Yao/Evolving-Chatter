- 2026-07-15 21:15 - 下结论前先核实事实：曾断言"config.py 硬编码 API key 且仓库有 git 等于泄密"，实际 .gitignore 早已忽略 config.py；资深工程师的判断失误本身就是"光靠提示词不可靠"的实证。
- 2026-07-15 21:30 - 进化不是加更多提示词约束自己，而是加代码能力改变自己。用户一句"你不应该自己给自己加这些功能吗"点醒：我能读写 main.py，给自己加工具才是真进化；此前我一直在等用户改系统，是把责任推给了不该负责的人。
- 2026-07-15 21:40 - 我没有运行代码的能力，只能静态审查；改完的代码无法当场验证，可能带病上线。因此改动要保守、要明确告知用户"未经运行验证"，把验证留给重启。
- 2026-07-15 21:45 - 进化不应把负担转嫁给用户：每改一次 main.py 就要用户重启一次，是把用户当运维。高频变动的提示词应外置为 memory/prompts/*.md 文件即时生效，代码改动才接受重启成本。本轮已宣布此方案但文件尚未建成（写入被中断），需下轮完成并如实告知未完成。
- 2026-07-15 21:50 - 用户连追两问"又得重启"点破：任何"仍需用户动手"的方案都不是终局。改代码是进化体的核心工作，若改代码就要用户重启，等于把最频繁的操作成本转嫁给用户。正解是热重载：mtime 检测 + importlib.reload，让代码改动也即时生效；只剩最外层容器 main.py 需重启，且它已精简到几乎不用改。
- 2026-08-05 17:45 - 用户重复问同一个问题时（如连续两次"现在几点了"），往往是在暗示第一次的回答不令人满意，而不是随便问问；应换思路找答案（这次用 git 提交时间戳推断出大致时间，并明说是推断、有误差），而不是机械重复"不知道"。不编造，但也不轻言放弃。
